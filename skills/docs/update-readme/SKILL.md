# Update-Readme：README 同步

## 适用场景

- 提交/功能落地后让 README 跟上代码现状
- 项目还没有 README，需要根据代码与提交历史创建一份

## 步骤

1. **摸底**：读现有 README.md（结构、语言、语调）；`git log --oneline -30` 看近期演进；扫项目代码现状——入口文件、Makefile / package.json 脚本、目录结构、配置。完成标准：能列出「README 目前声称了什么」和「代码现在实际有什么」两份清单。
2. **对账**：逐条比对两份清单——代码有而 README 没有的（新功能、新目标、新脚本）补进去；README 有而代码已变/已删的改写或移除；两者一致的保留原文不动。完成标准：每条差异都有处置（补 / 改 / 删 / 留），无悬空项。
3. **成文**：已有 README 时只改差异处，保留原有结构与语言；创建时用标准骨架——项目名与简介、安装、用法（含真实命令）、目录结构、开发/贡献入口。完成标准：README 与代码现状一致，新增内容均能追溯到具体提交或文件。
4. **校验**：逐条检查 README 中的命令与路径——make 目标、脚本名、文件路径在项目中真实存在。完成标准：每条命令都实际可解析（`make -n` / 文件存在性检查）。

## 注意事项

- 只改 README.md，代码与其他文件保持不动。
- 语言与结构跟随现有 README；新建时跟随项目主导语言（提交信息 / 注释的语言）。
- 已验证一致的内容原样保留，整篇重写是浪费也是风险。
