# Read：项目通读与 READ.md 生成

## 适用场景

- 为当前工作区或指定项目生成详细的中文学习文档 READ.md

## 步骤

1. **定界**：确定目标项目——用户指定了路径就读该路径，默认当前工作区。读根目录 README、包管理清单（package.json / pyproject.toml / go.mod 等）和 .gitignore，确定项目类型。完成标准：能一句话说出项目是什么、用什么技术栈。
2. **先树**：全量清点文件树（`git ls-files` 或等价方式，跳过 .gitignore 覆盖与依赖目录），把每个目录标记为「核心待读」或「归类即可」——入口、配置、路由、核心模块、测试样例进前者。完成标准：文件树无遗漏，每个目录都有标记。
3. **后文**：通读全部「核心待读」文件。完成标准：核心清单逐个消号，无跳过项。
4. **成文**：按固定七段骨架（见下）写出 READ.md，落在项目根目录；已有 READ.md 则整篇重写覆盖。完成标准：七段齐全，缺内容的段落写「不适用」而非删除；每个源码目录都被归属到某段叙述。
5. **校对**：对照文件树逐段核对——目录结构段与真实树一致，抽查的路径、文件名在项目中真实存在。完成标准：抽查全中。

## READ.md 七段骨架

1. **项目概述**：项目是什么、解决什么问题、当前状态。
2. **技术栈与依赖**：语言、框架、关键依赖及各自用途。
3. **目录结构**：真实文件树（裁剪到有信息量的层级），逐目录注一句职责。
4. **核心模块详解**：每模块三件事——职责、关键文件（含路径）、对外接口（函数/命令/API）。
5. **数据流与调用链**：一次典型请求/命令从入口到落点的完整路径。
6. **构建·运行·测试**：从零把它跑起来的命令序列。
7. **坑与注意事项**：非直觉约定、易错点、隐藏耦合。

## 注意事项

- READ.md 是生成物快照：每次整篇重写、直接覆盖，旧版的手写批注会丢失。
- 中文行文，代码、路径、命令、专有名词保留英文，术语首现括注，如「深度模块（deep module）」。
- 项目缺 README 或清单文件时，直接从配置与入口代码推断，七段照常写全。
